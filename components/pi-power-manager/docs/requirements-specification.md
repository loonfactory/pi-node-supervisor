## 1. 개요

### 1.1 목적

본 문서는 `pi-power-manager`의 초기 개발 범위에 대한 소프트웨어 요구사항을 정의한다. 시스템이 제공해야 하는 기능·인터페이스·품질 요구사항과 우선순위 및 검증 방법을 확정하며, 내부 구조, 모듈 분해, API 형식과 구체적인 구현 방식은 설계서에서 정의한다. 본 문서에 기술되지 않은 요구사항은 미확정으로 간주한다.

### 1.2 적용 범위

본 문서는 기획서 PLAN-PIPOWERMANAGER-001의 3.3 초기 개발 범위를 기준으로 한다. 공식 지원 대상은 Raspberry Pi 5와 Raspberry Pi OS 64-bit headless 환경이며, 내장 RTC와 wake alarm을 이용한 단일 장치의 예약 종료·기동을 다룬다.

기획서 3.2에서 제외한 외부 전원 차단, 외장 RTC·UPS·전원 HAT, 웹 UI, 다중 장치 중앙 관리 및 Raspberry Pi 5 이외 하드웨어는 요구사항 대상이 아니다. 구현 방향은 정해졌으나 초기 마일스톤에서 제외한 기능은 P4로 등재할 수 있다.

### 1.3 용어

기획서 1.3의 용어를 승계하며 다음 용어를 추가로 정의한다.

- **활성 일정:** 다음 동작 계산에 참여하도록 설정된 일정이다.
- **다음 동작:** 현재 시각 이후 가장 먼저 실행해야 하는 종료 또는 기동 의도다.
- **소유 알람:** 시스템이 기록하고 런타임 상태에 그 식별 정보가 남아 있는 wake alarm이다.
- **외부 알람:** 소유 알람으로 확인할 수 없는 기존 wake alarm이다.
- **최소 준비 시간:** RTC 기록과 안전 종료에 필요한 시간을 확보하기 위해 현재 시각과 다음 기동 시각 사이에 요구하는 최소 간격이다.
- **놓친 동작:** 서비스 중지, 시계 변경 또는 전원 상실 때문에 예정 시각에 실행되지 못한 동작이다.
- **검증 방법:** Unit은 외부 장치 없이 수행하는 자동화 시험, Integration은 운영체제 경계나 가짜 RTC를 포함한 자동화 시험, HIL은 실제 Raspberry Pi 5 하드웨어 시험, Scenario는 정해진 절차로 수행하는 수동 또는 반자동 시험이다.

### 1.5 요구사항 표기

요구사항 ID는 `영역접두-일련번호` 형식으로 한다. 접두는 SCH(일정), RTC(RTC 및 알람), PWR(종료·기동 조정), STA(상태·진단), CFG(설정·영속화), CLI(명령행), IF-RTC(RTC 어댑터 계약), IF-PWR(전원 조정 계약), NFR(비기능)로 한다. 삭제된 번호는 재사용하지 않는다.

| 등급 | 정의 | 설명 |
|---|---|---|
| P1 | 우선 | 핵심 안전 조건 또는 다른 요구사항의 전제로, 해결 없이는 출시할 수 없다. |
| P2 | 중간 | 출시 전에 필요하지만 P1 완료 후 구현할 수 있다. |
| P3 | 낮음 | 리소스와 일정에 따라 선택하며, 미구현 시 알려진 제한사항으로 기록한다. |
| P4 | 보류 | 구현 방향은 검토 중이거나 확정되었지만 초기 마일스톤에서 제외한다. |

요구사항의 출처가 자명하지 않은 경우 `(근거: PLAN-PIPOWERMANAGER-001 절 번호)` 형식으로 근거를 기록한다. 관련 TC는 시험 명세 작성 시 연결한다.

## 2. 시스템 개요

### 2.1 구성

시스템은 기획서 2.1에 정의된 Scheduler, RTC Adapter, Power Coordinator, Service 및 CLI로 구성한다. Scheduler는 시간과 일정에 대한 순수 계산을 담당하고, RTC Adapter는 Linux RTC 경계를, Power Coordinator는 종료 가능 여부와 실제 종료 요청을 담당한다. Service는 이 구성 요소를 systemd 환경에서 실행하며, CLI는 관리 기능을 제공한다.

### 2.2 동작 개요

시스템은 부팅 시 환경과 저장 상태를 점검하고 다음 종료·기동 시각을 계산한다. 종료 시각에는 훅을 실행한 뒤 다음 기동 시각을 RTC wake alarm에 기록하고 read-back 검증한다. 검증에 성공한 경우에만 정상 종료를 요청한다. 부팅 후에는 저장된 일정과 이전 상태를 바탕으로 다음 동작을 다시 계산한다.

관리형 종료의 결과는 다음 두 상태 중 하나로 종결되어야 한다.

- **종료 수행:** 유효한 다음 기동 알람과 모든 사전 조건이 확인되어 정상 종료를 요청했다.
- **가동 유지:** 어느 조건이든 충족하지 못해 종료하지 않고 원인을 기록했다.

어느 상태로도 판정되지 않은 채 종료 절차가 중단되어서는 안 된다.

### 2.3 전제 조건 및 제약사항

- 대상 하드웨어는 Raspberry Pi 5다.
- 운영체제는 systemd와 Linux RTC sysfs를 제공하는 Raspberry Pi OS 64-bit다.
- RTC wake alarm 대기 중에도 외부 주 전원은 연결되어 있어야 한다.
- 부트로더에는 RTC 저전력 기동에 필요한 설정이 적용되어 있어야 한다.
- RTC 백업 배터리는 주 전원 단절 시 시각 보존을 위해 권장하되, 주 전원 없이 보드를 기동시키지는 않는다.
- 초기 버전은 단일 장치·단일 시스템 RTC를 전제로 한다.
- 네트워크 및 NTP는 정상 동작의 필수 조건이 아니다. 단, 시스템 시각과 RTC 시각 중 적어도 하나는 신뢰할 수 있어야 한다.
- 실제 시스템 종료와 RTC 쓰기에는 운영체제 권한이 필요하다.

## 6. 요구사항 추적 및 완료 조건

### 6.1 추적 원칙

- 모든 구현 작업은 하나 이상의 요구사항 ID를 참조한다.
- 모든 P1과 P2 요구사항은 출시 전 하나 이상의 TestCase와 연결한다.
- P4 요구사항은 초기 출시 완료 판정에서 제외하고 구현 시 우선순위를 재분류한다.
- 설계 결정이 요구사항의 의미를 변경하면 SRS를 먼저 개정하고 변경 이력을 남긴다.
- 관련 TC 열은 TEST-PIPOWERMANAGER-001 작성 시 실제 테스트 ID로 갱신한다.

### 6.2 초기 출시 완료 조건

- 모든 P1 요구사항이 구현되고 연결된 시험을 통과한다.
- 모든 P2 요구사항이 구현·검증되거나 승인된 제한사항으로 명시된다.
- Pi 5 실기기에서 NFR-005 반복 기동 시험을 통과한다.
- RTC 알람 기록 또는 검증 실패 시 종료하지 않는 PWR-003, PWR-008 및 NFR-007을 실기기 또는 장애 주입으로 확인한다.
- 알려진 제한 사항, 설치 전제, 복구 절차와 외부 전원 연결 조건을 사용자 문서에 포함한다.
